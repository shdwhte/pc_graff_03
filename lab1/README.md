# Лабораторна робота №1. Основи створення найпростішої WebGL-програми

**Мета:** отримати практичні навички програмування WebGL-програм, які дозволяють створювати графічні об'єкти та анімації.

## Структура проєкту

```
lab1/
├── index.html   # сторінка з елементом canvas
├── main.js      # керуючий код (JavaScript) і шейдери (GLSL)
└── README.md    # опис роботи
```

## Запуск

Відкрийте `index.html` у браузері (Chrome, Firefox, Opera). Якщо потрібні ES-модулі (`type="module"`), запускайте через локальний сервер, наприклад Live Server у VS Code, бо при відкритті файлу подвійним кліком модулі блокуються політикою CORS. У цій роботі використано звичайний скрипт з атрибутом `defer`.

Помилки шейдерів дивіться в консолі браузера (F12).

## Основні поняття

- **WebGL** це JavaScript API для 2D- і 3D-графіки в елементі `<canvas>` без плагінів. Використовує апаратне прискорення GPU і відповідає OpenGL ES 2.0.
- **Програма WebGL** складається з керуючого коду на JavaScript і шейдерів на GLSL, які виконує GPU.
- **Графічний конвеєр:** вхідні дані (атрибути, уніформи), вершинний шейдер, кліппінг, перетворення у в'юпорт, растеризація, фрагментний шейдер, компонування, вихідне зображення.
- **Вершинний шейдер** запускається для кожної вершини й записує її позицію в `gl_Position`.
- **Фрагментний шейдер** запускається для кожного пікселя фігури й записує колір у `gl_FragColor`.
- **Система координат WebGL:** кожна вісь має діапазон від -1.0 до 1.0, центр екрана це (0, 0).

## Крок 1. Canvas, контекст WebGL, viewport, колір екрану

**Що зроблено:** створено HTML-сторінку з `<canvas>`, функцію `setupWebGL`, ініціалізацію через `window.onload`, задано viewport і колір очищення.

| Елемент | Призначення |
|---|---|
| `<canvas>` | Область, у якій WebGL малює. Атрибути `width` і `height` задають розмір у пікселях |
| `defer` у `<script>` | Скрипт виконується після розбору сторінки, тому canvas уже існує |
| `setupWebGL(canvas)` | Викликає `canvas.getContext("webgl")` і створює графічний контекст `gl`. Перевірка на `null` потрібна, бо на деяких пристроях WebGL недоступний |
| `window.onload = init` | Запускає код після повного завантаження сторінки |
| `gl.viewport(x, y, w, h)` | Задає прямокутник у пікселях, куди відображаються нормалізовані координати. Це 3-й етап конвеєра |
| `gl.clearColor(r, g, b, a)` | Запам'ятовує колір очищення (значення 0.0-1.0), сама нічого не малює |
| `gl.clear(gl.COLOR_BUFFER_BIT)` | Заливає буфер кольору обраним кольором |

## Крок 2. Шейдери та кольоровий трикутник

**Що зроблено:** написано вершинний і фрагментний шейдери, налаштовано буфер вершин, намальовано трикутник, кожна вершина якого має свій колір.

**Шейдери**

- `attribute`: вхідні дані, різні для кожної вершини (позиція `aPosition`, колір `aColor`).
- `varying`: канал передачі даних від вершинного до фрагментного шейдера. Між вершинами значення інтерполюється, тому виходить плавний градієнт.
- `gl_Position` має 4 компоненти (x, y, z, w), тому до 2D-позиції додаємо `0.0` і `1.0`.
- `precision mediump float;` обов'язковий у фрагментному шейдері, інакше він не скомпілюється.

**Допоміжні функції**

- `createShader(type, source)`: створює шейдер, компілює його й перевіряє помилки.
- `createProgram(vs, fs)`: лінкує вершинний і фрагментний шейдери в одну програму. `gl.useProgram` робить її активною.

**Буфер вершин**

Кожна вершина зберігає 5 чисел: `x, y, r, g, b`.

| Виклик | Призначення |
|---|---|
| `gl.createBuffer()`, `gl.bindBuffer()` | Створюють буфер у пам'яті GPU й роблять його поточним |
| `gl.bufferData()` | Копіює дані з JavaScript у буфер GPU |
| `gl.getAttribLocation()` | Повертає номер атрибута в шейдері за іменем |
| `gl.vertexAttribPointer(loc, size, type, normalized, stride, offset)` | Пояснює GPU, як читати буфер |
| `gl.enableVertexAttribArray()` | Вмикає атрибут, без цього він не працює |
| `gl.drawArrays(gl.TRIANGLES, 0, 3)` | Малює трикутник із 3 вершин |

Параметри `vertexAttribPointer` для нашого буфера:

- `size`: 2 для позиції, 3 для кольору;
- `stride`: 5 чисел × 4 байти = 20 байтів на вершину;
- `offset`: 0 для позиції, 2 × 4 = 8 байтів для кольору.

## Крок 3. Квадрат і його обертання

**Що зроблено:** додано другий трикутник, разом вони утворюють квадрат по центру екрана. Квадрат обертається навколо власного центру через `requestAnimationFrame`.

**Квадрат із двох трикутників**

- WebGL малює лише точки, лінії й трикутники, тому чотирикутник складається з двох трикутників зі спільною діагоналлю. Це 6 вершин.
- Центр квадрата в точці (0, 0), тож він розташований по центру екрана.
- На canvas 640×480 розміри 0.8 × 1.0 у координатах WebGL дають приблизно квадрат (256 × 240 пікселів).

**Обертання**

- `uniform float uAngle`: змінна, однакова для всіх вершин за один кадр. Значення передається з JavaScript через `gl.uniform1f`.
- Формула повороту навколо початку координат:
  - `x' = x·cos(a) − y·sin(a)`
  - `y' = x·sin(a) + y·cos(a)`
- Обчислення виконується у вершинному шейдері, тому масив вершин у JavaScript не змінюється, змінюється лише кут.

**Анімація через `requestAnimationFrame(render)`**

- Браузер викликає `render` перед кожним новим кадром (зазвичай 60 разів на секунду). Виклик усередині самої `render` створює цикл.
- Браузер передає час у мілісекундах. Множення на `0.001` переводить його в секунди.
- `deltaTime` це час між кадрами. Кут збільшується на `ROTATION_SPEED × deltaTime`, тому швидкість не залежить від частоти кадрів монітора.
- `gl.clear` на початку кожного кадру стирає попереднє зображення.
- Швидкість обертання змінюється константою `ROTATION_SPEED`.

## Режими `gl.drawArrays(mode, first, count)`

| Режим | Що малює |
|---|---|
| `gl.POINTS` | Окремі точки |
| `gl.LINES` | Лінію між кожною парою вершин |
| `gl.LINE_STRIP` | Ламану лінію |
| `gl.LINE_LOOP` | Замкнену ламану лінію |
| `gl.TRIANGLES` | Трикутник для кожної трійки вершин |
| `gl.TRIANGLE_STRIP` | Смугу трикутників |
| `gl.TRIANGLE_FAN` | Трикутники у вигляді віяла навколо першої вершини |
